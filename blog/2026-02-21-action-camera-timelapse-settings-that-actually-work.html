The Action Camera Timelapse Settings I Actually Use

By Pranav Arya · PAFP · #action-camera · #timelapse · #tutorial · #gopro

Default timelapse settings on most action cameras produce results that flicker and jump in a way that reads as amateur the moment a client actually watches the footage on a real screen rather than a phone preview. A few specific setting changes fixed this consistently enough that I now apply them as a default rather than fighting the auto settings every time.

Lock exposure before you start, always

Auto exposure recalculating between individual timelapse frames is the single biggest cause of visible flicker, a cloud passing over causing one frame to be noticeably brighter than its neighbors. Locking exposure manually before starting means giving up some dynamic range flexibility across a changing scene, sunrise and sunset timelapses specifically, but the trade-off is worth it for the vast majority of shorter timelapse sequences where lighting stays relatively consistent across the capture window.

Interval choice depends entirely on subject speed, not a universal default

I stopped using one default interval for everything. Fast-moving subjects, crowds, traffic, need a tighter interval, often a second or under, to avoid a jarring stroboscopic jump between frames. Slow subjects, clouds, shadows moving across a landscape, can use a much longer interval without losing smoothness, and using a short interval there just means more frames to process for no visual benefit.

  • Lock exposure manually before starting any timelapse sequence
  • Match interval length to actual subject speed, not a universal default
  • Shoot slightly longer than needed, trimming in post beats a sequence cut short

The post-production step that fixes remaining flicker

Even with locked exposure, minor frame-to-frame brightness variation still shows up occasionally, and a deflicker pass in editing catches what manual settings alone don't fully solve. It's a quick automated process in most editing software now, and running it as a default step on every timelapse sequence rather than only when flicker is obviously visible has caught subtle issues I wouldn't have noticed until a client did.
